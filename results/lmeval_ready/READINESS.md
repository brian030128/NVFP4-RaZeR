## Harness and version

**Recommendation: lm-eval 0.4.11**, the version pinned in `sm120/requirements.lock.txt`, with the datasets pinned by
`lm_eval_datasets.py`. Reasons:
- **It runs as installed.** It works with transformers 5.16.1 without the `lm_eval_compat` shim that 0.4.5 and 0.4.9.1
  need (their module-level `AutoModelForVision2Seq`); 0.4.9.1 also needs `peft`.
- **Its datasets are namespaced Hugging Face repos with no dataset scripts**, so nothing needs `trust_remote_code`.
- **Same prompts:** the three versions build identical requests for this suite (below).

**Checked differences between 0.4.5, 0.4.9.1 and 0.4.11:**
- **Task configs** (`versions.md`, generated by `compare_versions.py`): byte-identical except the dataset ids
  (`hellaswag` → `Rowan/hellaswag`, and so on) and `trust_remote_code` (hellaswag, piqa and winogrande in 0.4.5).
- **Requests** (`requests.md`, generated by `compare_requests.py`): for the first 20 documents of every task (gsm8k:
  5, with its 5 few-shot examples at seed 1234), every context and continuation (gsm8k: context and generation
  settings) is identical across the three versions. That is 445 requests.
- **Metric code** (AST comparison): `acc`, `acc_norm` and `exact_match` are unchanged. `process_results` gained new
  metrics (`acc_bytes`, `likelihood`) that this suite does not use. The gsm8k regex filter now maps a non-string
  response to `''`.
- **Tokenization: a real difference.**
  - 0.4.5 and 0.4.9.1 default to `add_bos_token=False` and encode every context without special tokens, so no BOS.
  - 0.4.11 defaults to `add_bos_token=None` and keeps the tokenizer's default, so Llama-3.1 and Mistral contexts start
    with BOS. 0.4.11 also avoids a double BOS.
  - Scores from 0.4.11 are therefore not comparable with the earlier 0.4.5 zero-shot numbers
    (`MIXFP4_REPORT_DETAILS.md`) for models whose tokenizer adds BOS. `HFLM(add_bos_token=False)` reproduces the old
    behaviour.
  - Recommended: the 0.4.11 default, BOS as in training. The smoke test records per model whether contexts start
    with BOS (`tokenization` in each report).
  - Measured: Llama and Mistral contexts start with BOS; Phi-4 and Qwen add none, so for those two the versions
    tokenize identically.
- **Checked on the GPU** (Llama-3.1-8B BF16, the smoke subsets; `smoke.md`, version cross-check):
  - lm-eval 0.4.5 and 0.4.11 with `--no-bos` give the same result on every example: 140/140 multiple-choice
    examples, and 5/5 gsm8k generations with identical text.
  - 0.4.11 with its default BOS changes 7 of the 140 multiple-choice results and 3 of the 5 gsm8k generations.
  - So the three harnesses differ only in the BOS token.

## Evaluation paths

`run_lmeval_deploy.py` evaluates a model loaded exactly as in the Parts 2–3 PPL evaluation (`run_ppl_deploy.py`'s
loader, scope and weight checks) through lm-eval's `HFLM(pretrained=model)`, one policy at a time:
- **BF16:** the model as loaded.
- **Fake (c):** `sm120/eval/common.FakeQuant`. The weights are the artifact's fake-quant weights (FourOverSix, or the
  TC map with E0M3 α=1 on its tiles). The activations get per-token FourOverSix (`quantize_rows`) through a pre-hook
  on every quantized Linear.
- **NativeLinear (c):** the SM120 packed artifact, installed as in the PPL evaluation. The kernel follows the type
  block (FourOverSix: `auto_stock`; 16x64: `auto`; 8x64: `n8k64_wB`). Activations are quantized per token
  (convention (c)) by sm120's CUDA activation quantizer. Coverage is checked after each policy: every quantized Linear
  ran natively, with no fallback and no remaining BF16 Linear.
- **Batching under convention (c):** with per-token activation scales, the quantization of a request's activations
  does not depend on the other requests or the padding in its lm-eval batch. The older per-batch-tensor convention of
  the 0.4.5 zero-shot script did. What remains is floating-point: GEMM algorithms may differ with the batch shape.

## How to run

```bash
python run_lmeval_deploy.py --model llama8b --data-root $DATA --transformers-deviation \
    --evaluate BF16=bf16 --evaluate FourOverSix=native:artifacts/llama8b_fo6 --evaluate tc-16x64=native:artifacts/llama8b_tc_16x64 \
    --evaluate tc-16x64-fake=fake:map:artifacts/llama8b_tc_16x64.mixfp4map --out eval/llama8b_lmeval
```

Without `--limit`, every document is evaluated. Add `--tasks` to pick tasks and `--repeat LABEL` for a
determinism check.
